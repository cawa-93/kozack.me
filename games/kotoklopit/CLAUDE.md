# Котоклопіт

Гра з розділу ігор сайту, публікується за адресою `/games/kotoklopit/`. Правила цього файлу діють лише в межах теки гри.

## Як працюємо

Claude Code працює локально на комп'ютері автора, з великим лімітом використання, але інтернет нестабільний. Працюємо блоками: блок — кілька пов'язаних змін однієї механіки.

- **Кожна логічна зміна — окремий коміт** (локально, одразу). Комітимо часто, не накопичуючи.
- **Пуш — лише після закінчення великої правки** — загальне правило проєкту (кореневий `CLAUDE.md`, «Як працюємо»): `git push` у `master` один раз, коли блок готовий і перевірений. Якщо мережа впала — працювати далі, а пуш повторити пізніше; робота не чекає на мережу.
- **§12 «Стан і що далі» в `GAME_DESIGN.md` оновлюється наприкінці блоку** (окремим комітом чи разом з останньою зміною): що зроблено, що в роботі, що далі й відомі проблеми. Новий контекст починає роботу з нього.
- Правки — прямо в `master`, без окремих гілок і PR: кожен пуш — деплой гри на сайт. Гру випущено PR [#213](https://github.com/cawa-93/kozack.me/pull/213).

**Перевірки:**

- **Тести — комплексно** — загальне правило проєкту (кореневий `CLAUDE.md`). Тут: під час роботи — `npm run typecheck -w games/kotoklopit` і тести своєї ділянки (`npx vitest run tests/<файл>` у `games/kotoklopit`); увесь набір `npm test -w games/kotoklopit` — наприкінці блоку (перед пушем) і після зведення гілок. Перед першим прогоном після нових файлів у `scenarios/`, `tests/fixtures/saves/`, `src/view/art/manifest/`, `src/audio/sfx/groups/` чи `audio/sfx/` — `npx vitest --clearCache`: інакше `import.meta.glob` бачить старий перелік.
- Раз наприкінці блоку: `npm run build -w games/kotoklopit`, якщо зачеплено сцени, графіку чи конфіг; короткий баланс `BALANCE_WEEKS=2 BALANCE_SEEDS=1 npm run balance -w games/kotoklopit`, якщо змінилася поведінка (`balance/REPORT.md` після короткого прогону не комітити — `git checkout`).
- Повний баланс (`BALANCE_WEEKS=20 npm run balance -w games/kotoklopit`, 20 тижнів × 3 seed; без `BALANCE_WEEKS` — лише 6 тижнів) — наприкінці великої механіки, з комітом `balance/REPORT.md`.
- Не комітити `.idea/` і згенероване (`balance/TRACE.txt`, `public/games/`).

**Перевірка в браузері — лише коли це справді потрібно** — загальне правило проєкту (кореневий `CLAUDE.md`). Локально — `npm run dev -w games/kotoklopit` і скриншоти (playwright-core з кореня, браузер Edge: `channel: "msedge"`). Сценарій — `?scenario=<назва файлу з scenarios/>`. Знімки всіх сценаріїв детерміновано — `npm run shots -w games/kotoklopit -- --out <тека>` (свій Vite на вільному порту; `--scenario`, `--size`, `--ms`; `--cache-key <назва>` — свій кеш Vite, коли в тій самій копії гри паралельно знімає ще хтось); порівняти дві теки попіксельно — `-- --compare <A> <B> --diff <тека>`. Галерея арту (`art/STYLE.md`, §15) — `gallery.html` (лише в режимі розробки й на прев'ю); знімки її вкладок — `-- --page gallery [--tab slice,frames] [--bg light,dark]`. Каталог звуків — `sounds.html` (так само лише в режимі розробки й на прев'ю): автор слухає кожен звук і вирішує «затверджено / замінити / видалити»; рішення dev-сервер пише в `audio/sfx/review.json` (`audio/SOUND.md`, «Ефекти»). Пуш у `master` деплоїть сайт без режиму розробки (прев'ю з ним Netlify збирає лише для гілок PR); збірки обмежені — пушимо лише готовий блок (вище). Коли зміну варто перевірити очима, наприкінці відповіді коротко сказати, що саме й у якому сценарії подивитися.

**Відповіді в чаті** — коротко, без великих таблиць і довгих логів: що зроблено, що перевірити, що далі.

## Джерела правди

- `GAME_DESIGN.md` — єдиний стан гри й єдине джерело правди про неї. Лише поточний стан: зміну вносимо прямо в текст, без позначок, дат і історії; історія — у git.
- Довідники: `BREEDS.md`, `TRAITS.md`, `DISEASES.md`, `DAY_MODIFIERS.md`, `TEXTS.md`, `WARDROBE.md` (гардероб персонажа). Правила арту й конвеєр — `art/STYLE.md`; звук (радіо, ефекти, ліцензії й конвеєр) — `audio/SOUND.md`. Вони теж описують лише поточний стан.
- **Спершу дизайн-документ, потім код.** Якщо рішення змінюється або бракує правила чи числа, спершу оновити `GAME_DESIGN.md`, потім код. Якщо код і документ розходяться, сказати про це, а не мовчки змінювати дизайн.

## Код

- Phaser 4, TypeScript (strict), Vite, Vitest.
- `src/sim/` — симуляція: чистий TypeScript без Phaser і DOM (це перевіряє тест), щоб її можна було запускати в Node (§2.1, §11.2). Стан гри — звичайні дані, які зберігаються в JSON.
- Числа гри — лише в `src/sim/config.ts`, з посиланням на розділ документа; у `GAME_DESIGN.md` замість числа — назва константи (`GUESTS.ringLead`).
- Випадковість у симуляції — лише через `src/sim/rng.ts` і потоки з §6.1; `Math.random` — тільки для seed нової гри.
- `src/scenes/` — сцени Phaser: вони показують стан і передають дії гравця в симуляцію, але самі правил гри не містять. Малювання квартири, персонажа, баблів, інтерфейсу, сенсорного керування й камера — у `src/view/`, картки поверх гри (DOM) — у `src/ui/`, тексти гри — у `src/texts.ts`.
- `src/session.ts` — поточна гра в браузері: збереження в `localStorage`, швидкість і пауза режиму розробки.
- `src/screen.ts` — екран браузера: повноекранний режим, орієнтація й безпечна зона (виріз камери телефона).
- Симуляція повідомляє про те, що сталося, подіями (`src/sim/events.ts`): з них сцена показує бабли й картки, а режим розробки веде журнал. Стан гри від підписників не залежить.
- Режим розробки (§11.5) — лише в `src/dev/`, а підключає його тільки `main.ts` динамічним імпортом під `__DEV_TOOLS__` (це перевіряє тест). `__DEV_TOOLS__` задає `vite.config.ts`: увімкнено в `npm run dev` і на прев'ю-деплоях Netlify (змінна `CONTEXT`), вимкнено в продакшн-збірці. Що режим розробки потребує поза `src/dev/` (поля `Session` — `speed`, `paused`, `showHidden`, `lightAt`; приховані числа `src/view/iso/hiddennums.ts`; позначка знімків `markArtReady`), — лише під `__DEV_TOOLS__`, щоб продакшн-збірка це викидала (поля сесії й приховані числа перевіряє тест). Сценарії — файли `scenarios/*.json`; запуск — `?scenario=<назва файлу>`. Новий сценарій для перевірки механіки варто класти туди ж: ті самі сценарії використовують тести.
- Ключі `localStorage` — з префіксом `kotoklopit:`.
- **Збереження гравців не ламаємо** (§4.2). Гру випущено: після кожної зміни мають відкриватися й гратися збереження, які вже є в гравців. Це стосується стану (`Save`, `GameState` у `src/sim/types.ts`) і всього, що в ньому лежить за назвою: id модифікаторів, товарів, речей, рис, хвороб, порід, пунктів, значень складності. Нове поле — необов'язкове, і без нього гра поводиться, як досі (як `utilitiesBill` чи поля гардеробу в `Look`). Перейменувати чи видалити поле або значення, змінити його зміст чи одиниці — лише з міграцією: файл у `src/sim/migrations/` і рядок у кінці `MIGRATIONS` (`src/sim/saves.ts`); вона проходить усі знімки стану (`snapshots`), а версія піднімається сама. Випущену міграцію й записані зразки не змінюють. `tests/saves.test.ts` відкриває зразки кожної випущеної версії (`tests/fixtures/saves/`) і грає з них далі: якщо він падає, зміна несумісна — виправляти код чи додавати міграцію, а не зразок. Нова версія — разом із набором зразків, записаним уже новим кодом (`SAVES_RECORD=<набір> npx vitest run tests/saves.test.ts`; без нього тест падає); велика необов'язкова зміна формату — теж варто записати свій набір. Вподобання поза збереженням (`kotoklopit:audio`) — так само: невідоме чи зіпсоване значення дає типове.
- Тексти гри українською, правила текстів — у `TEXTS.md`. Коментарі в коді теж українською.
- Нова механіка — з тестами в `tests/`.
- **Кожна відмова — своя іконка** (§11.4). Дія не вдалася — `refuse` з причиною, яка каже, що саме заважає (`Refusal` у `src/sim/events.ts`), а не загальне «не можна» чи тиша. Нова причина — нова іконка в `refusalBubble` (`src/view/symbols.ts`); тест `tests/refusals.test.ts` перевіряє, що бабли всіх причин різні.
- **Унікальна іконка на унікальний кейс** (§11.4). Ширше за попереднє: кожен окремий випадок — що бабл події, стан, думка, індикатор чи значок на панелі каже гравцеві — має свою іконку, а та сама іконка (з тією самою позначкою «0», ✗, ?, ✓) — лише для того самого значення, хоч би хто й як це казав. Голод кота думкою й проханням вголос — той самий випадок (корм в обох; вид бабла й так їх розрізняє), а переляк кота й «!» терпіння над комп'ютером — різні. Новий бабл, стан чи думка — спершу перевір, чи це не той самий випадок, що вже є: інший — нова назва в `ICON_NAMES` (`src/view/iconnames.ts`), запис у маніфесті арту (`src/view/art/manifest/a11-icons.ts` чи `a12-icons.ts`) і малюнок `art/icon/<назва>.svg` (без SVG збірка й тести падають); той самий — у групу одного значення з причиною. Відповідності «випадок → іконка» — у `src/view/symbols.ts` (`eventBubbles`, `refusalBubble`, `PRODUCT_ICONS`, `itemIcon`, `stoveIcon`, іконки показників і станів) і `thoughts.ts`; тест `tests/icons-unique.test.ts` збирає таблицю з цих функцій і перевіряє, що різні випадки мають різні іконки, крім явного переліку груп одного значення (§11.4, кожна — з поясненням).
- **Бабл — вголос чи думка** (§11.4). Новий бабл події — рядок у `eventBubbles` (`src/view/symbols.ts`): вголос (звук, мова, річ «каже» про свій стан) чи думка (що персонаж чи кіт відчуває, хоче, усвідомлює); думка — лише над персонажем чи котом, над річчю — ніколи (це перевіряє тип `Thinker` — і в `eventBubbles`, і в `Bubbles.setState` — та тест `tests/bubbles.test.ts`). Відмова — думка персонажа.
- **Утримання кнопки — одна дія.** Коли тривала дія з утриманням (пестощі, гра, прибирання, пилосос, будь-яка нова) закінчилася, а кнопку ще тримають, нова дія не починається, поки кнопку не відпустили: це робить `character.holdSpent` у `tickActivity` (`src/sim/actions.ts`). Дію, яка «закінчилася», але має лишитися видимою (кіт вкусив, награвся), позначай прапорцем на ній самій (`bitten`, `done`), а не обнуляй. Інакше утримання щокадру запускає ту саму дію знову, і її наслідки (штрафи, пробудження, події) повторюються щокадру — так уже було з грою й з пестощами після укусу. Для кожної нової дії з утриманням — тест: тримати кнопку довше за дію й перевірити, що вона спрацювала один раз.

## Команди

З кореня репозиторію:

- `npm run dev -w games/kotoklopit` — гра в режимі розробки;
- `npm test -w games/kotoklopit` — тести;
- `npm run typecheck -w games/kotoklopit` — перевірка типів;
- `npm run build -w games/kotoklopit` — збірка в `public/games/kotoklopit`.
