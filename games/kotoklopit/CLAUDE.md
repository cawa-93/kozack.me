# Котоклопіт

Гра з розділу ігор сайту, публікується за адресою `/games/kotoklopit/`. Правила цього файлу діють лише в межах теки гри.

## Як працюємо

З 2026-10-26 Claude Code працює локально на комп'ютері автора, з великим лімітом використання, але інтернет нестабільний. Працюємо блоками: блок — кілька пов'язаних змін однієї механіки (наприклад, один блок рішень автора за розбором).

- **Кожна логічна зміна — окремий коміт** (локально, одразу). Комітимо часто, не накопичуючи.
- **Пуш — наприкінці блоку** (і перед тим, як віддати відповідь), а не після кожного коміту: `git push origin new-game`. Якщо мережа впала — працювати далі, а пуш повторити пізніше; робота не чекає на мережу. Незакоміченого наприкінці відповіді не лишати.
- **План актуальний на кінець блоку.** Розділ «Де зупинились» у `IMPLEMENTATION_PLAN.md` оновлюється наприкінці блоку (окремим комітом чи разом з останньою зміною): що зроблено, що в роботі, що далі й відомі проблеми. Новий контекст починає роботу з нього.
- Гілка — `new-game` (PR [#213](https://github.com/cawa-93/kozack.me/pull/213) у `master`).

**Перевірки:**

- Перед кожним комітом — швидкі: `npm run typecheck -w games/kotoklopit` і `npm test -w games/kotoklopit` (кілька секунд; локально перед першим прогоном після нових файлів у `scenarios/` — `npx vitest --clearCache`).
- Раз наприкінці блоку: `npm run build -w games/kotoklopit`, якщо зачеплено сцени, графіку чи конфіг; короткий баланс `BALANCE_WEEKS=2 BALANCE_SEEDS=1 npm run balance -w games/kotoklopit`, якщо змінилася поведінка (`balance/REPORT.md` після короткого прогону не комітити — `git checkout`).
- Повний баланс (`BALANCE_WEEKS=50 npm run balance -w games/kotoklopit`, 50 тижнів × 3 seed; без `BALANCE_WEEKS` — лише 6 тижнів) — наприкінці великої механіки, з комітом `balance/REPORT.md`.
- Не комітити `.idea/` і згенероване (`balance/TRACE.txt`, `public/games/`).

**Перевірка в браузері:** локально — `npm run dev -w games/kotoklopit` і скриншоти (playwright-core з кореня, браузер Edge: `channel: "msedge"`), коли зачеплено графіку. Сценарій — `?scenario=<назва файлу з scenarios/>`. Знімки всіх сценаріїв детерміновано — `npm run shots -w games/kotoklopit -- --out <тека>` (свій Vite на вільному порту; `--scenario`, `--size`, `--gfx iso`); порівняти дві теки попіксельно — `-- --compare <A> <B> --diff <тека>`. Кожен пуш у `new-game` збирає прев'ю Netlify для PR #213 з увімкненим режимом розробки (посилання — у PR): там автор може подивитися гру й з телефона. Коли зміну варто перевірити очима, наприкінці відповіді коротко сказати, що саме й у якому сценарії подивитися.

**Відповіді в чаті** — коротко, без великих таблиць і довгих логів: що зроблено, що перевірити, що далі.

## Джерела правди

- `GAME_DESIGN.md` — єдине джерело правди про гру. Довідники: `BREEDS.md`, `TRAITS.md`, `DISEASES.md`, `DAY_MODIFIERS.md`, `TEXTS.md`.
- **Спершу дизайн-документ, потім код.** Якщо рішення змінюється або бракує правила чи числа, спершу оновити `GAME_DESIGN.md` з відповідною позначкою, потім код. Якщо код і документ розходяться, сказати про це, а не мовчки змінювати дизайн.
- `IMPLEMENTATION_PLAN.md` — покроковий план. Реалізується лише той крок, про який просили.

## Код

- Phaser 4, TypeScript (strict), Vite, Vitest.
- `src/sim/` — симуляція: чистий TypeScript без Phaser і DOM (це перевіряє тест), щоб її можна було запускати в Node (§2.1, §11.2). Стан гри — звичайні дані, які зберігаються в JSON.
- Числа гри — лише в `src/sim/config.ts`, з посиланням на розділ документа.
- Випадковість у симуляції — лише через `src/sim/rng.ts` і потоки з §6.1; `Math.random` — тільки для seed нової гри.
- `src/scenes/` — сцени Phaser: вони показують стан і передають дії гравця в симуляцію, але самі правил гри не містять. Малювання квартири, персонажа, баблів, інтерфейсу, сенсорного керування й камера — у `src/view/`, картки поверх гри (DOM) — у `src/ui/`, тексти гри — у `src/texts.ts`.
- `src/session.ts` — поточна гра в браузері: збереження в `localStorage`, швидкість і пауза режиму розробки.
- `src/screen.ts` — екран браузера: повноекранний режим, орієнтація й безпечна зона (виріз камери телефона).
- Симуляція повідомляє про те, що сталося, подіями (`src/sim/events.ts`): з них сцена показує бабли й картки, а режим розробки веде журнал. Стан гри від підписників не залежить.
- Режим розробки (§11.5) — лише в `src/dev/`, а підключає його тільки `main.ts` динамічним імпортом під `__DEV_TOOLS__` (це перевіряє тест). `__DEV_TOOLS__` задає `vite.config.ts`: увімкнено в `npm run dev` і на прев'ю-деплоях Netlify (змінна `CONTEXT`), вимкнено в продакшн-збірці. Сценарії — файли `scenarios/*.json`; запуск — `?scenario=<назва файлу>`. Новий сценарій для перевірки механіки варто класти туди ж: ті самі сценарії використовують тести.
- Ключі `localStorage` — з префіксом `kotoklopit:`.
- Тексти гри українською, правила текстів — у `TEXTS.md`. Коментарі в коді теж українською.
- Нова механіка — з тестами в `tests/`.
- **Кожна відмова — своя іконка** (правило автора 2026-10-25, §11.4). Дія не вдалася — `refuse` з причиною, яка каже, що саме заважає (`Refusal` у `src/sim/events.ts`), а не загальне «не можна» чи тиша. Нова причина — нова іконка в `refusalBubble` (`src/view/symbols.ts`); тест `tests/refusals.test.ts` перевіряє, що бабли всіх причин різні.
- **Бабл — вголос чи думка** (правка автора 2026-10-25, §11.4). Новий бабл події — рядок у `eventBubbles` (`src/view/symbols.ts`): вголос (звук, мова, річ «каже» про свій стан) чи думка (що персонаж чи кіт відчуває, хоче, усвідомлює); думка — лише над персонажем чи котом, над річчю — ніколи (це перевіряє тип `Thinker` — і в `eventBubbles`, і в `Bubbles.setState` — та тест `tests/bubbles.test.ts`). Відмова — думка персонажа.
- **Утримання кнопки — одна дія.** Коли тривала дія з утриманням (пестощі, гра, прибирання, пилосос, будь-яка нова) закінчилася, а кнопку ще тримають, нова дія не починається, поки кнопку не відпустили: це робить `character.holdSpent` у `tickActivity` (`src/sim/actions.ts`). Дію, яка «закінчилася», але має лишитися видимою (кіт вкусив, награвся), позначай прапорцем на ній самій (`bitten`, `done`), а не обнуляй. Інакше утримання щокадру запускає ту саму дію знову, і її наслідки (штрафи, пробудження, події) повторюються щокадру — так уже було з грою (2026-10-21) і з пестощами після укусу. Для кожної нової дії з утриманням — тест: тримати кнопку довше за дію й перевірити, що вона спрацювала один раз.

## Команди

З кореня репозиторію:

- `npm run dev -w games/kotoklopit` — гра в режимі розробки;
- `npm test -w games/kotoklopit` — тести;
- `npm run typecheck -w games/kotoklopit` — перевірка типів;
- `npm run build -w games/kotoklopit` — збірка в `public/games/kotoklopit`.
